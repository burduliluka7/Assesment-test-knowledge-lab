# 8. FORMAL OBJECTIVE — DELIVERABLE 0

At snapshot \(t\), let:

\[
H_t=(V_t,E_t)
\]

and let \(P\) be a partition of \(V_t\).

The hierarchy consists of:

\[
P_0,P_1,P_2,P_3,
\]

where:

- \(P_3\): singleton/fine level;
- \(P_2\): at most 120 clusters;
- \(P_1\): at most 40 clusters;
- \(P_0\): at most 12 clusters.

These are **display budgets**, not claims about natural numbers of communities.

State this explicitly.

## 8.1 Semantic compactness

For normalized embedding \(x_v\), cluster \(C\), centroid

\[
\mu_C=\frac{1}{|C|}\sum_{v\in C}x_v,
\]

define:

\[
S(P)=
\frac{1}{4|V_t|}
\sum_{C\in P}
\sum_{v\in C}
\|x_v-\mu_C\|_2^2.
\]

This is a normalized within-cluster semantic dispersion.

Lower is better.

The merge delta has the usual Ward form and can be updated efficiently.

# 9. NATIVE HYPERGRAPH STRUCTURAL TERM

Do **not** clique-project the native model.

For each hyperedge \(e\) and cluster \(C\), define:

\[
p_{e,C}
=
\frac{|e\cap C|}{|e|}.
\]

Define normalized edge fragmentation:

\[
f_e(P)=
\frac{
-\sum_{C:p_{e,C}>0}
p_{e,C}\log p_{e,C}
}{
\log |e|
}
\]

for \(|e|>1\).

Then:

\[
F(P)=
\frac{1}{|E_t|}
\sum_{e\in E_t}
f_e(P).
\]

Thus:

\[
0\le F(P)\le 1.
\]

Interpretation:

- \(F=0\): every hyperedge lies entirely within one supernode;
- large \(F\): hyperedge endpoints are scattered across many supernodes.

This directly uses the full endpoint distribution of each original hyperedge.

It also uses endpoint multiplicity when multiple members of a hyperedge fall into the same cluster.

Do not claim this statistic proves an irreducibly higher-order advantage over every pairwise representation.

Claim only what is justified:

> The native representation preserves hyperedge identity, arity, endpoint multiplicity and higher-order grouping during coarsening.

# 10. TEMPORAL REGULARIZER

Use construction-time temporal regularization.

Do not mistake post-hoc cluster matching for temporal regularization.

For a current partition \(P_t\) and previous partition \(P_{t-1}\), restrict both to the shared node set:

\[
U_t=V_t\cap V_{t-1}.
\]

Define:

\[
T(P_t,P_{t-1})
=
\frac{
VI(P_t|_{U_t},P_{t-1}|_{U_t})
}{
2\log |U_t|
}.
\]

Handle \(|U_t|<2\) safely.

The primary objective is:

\[
\boxed{
J_t(P)
=
\alpha S(P)
+
(1-\alpha)F(P)
+
\lambda T(P,P_{t-1})
}
\]

For the first snapshot:

\[
\lambda=0.
\]

Use a primary, a-priori configuration:

\[
\alpha=0.5
\]

and

\[
\lambda=0.2.
\]

Do not choose them by benchmark performance.

Explain:

- \(\alpha=0.5\) gives semantic and structural terms equal nominal status because both are normalized;
- \(\lambda=0.2\) treats history as a regularizer rather than allowing it to dominate current evidence.

Run a small sensitivity analysis only:

\[
\alpha\in\{0.25,0.5,0.75\}
\]

and

\[
\lambda\in\{0,0.1,0.2,0.4\}.
\]

Do not create dozens of configurations.

Do not tune on downstream benchmark results.

# 12. GREEDY MERGING

At each stage greedily choose the candidate merge that produces the smallest:

\[
\Delta J(A,B).
\]

Do not claim global optimality.

Explicitly say:

> The algorithm performs restricted-candidate greedy minimization of the stated objective.

## Candidate merge graph

Candidate-pair restriction is allowed for computational practicality.

Build an initial candidate graph using the union of:

1. semantic \(k\)-nearest-neighbor links;
2. pairs that co-occur in at least one native hyperedge.

Use:

\[
k=10.
\]

The hyperedge co-membership links are only a **candidate proposal mechanism**; they are not the structural objective.

The objective remains native-hypergraph fragmentation.

When clusters merge:

\[
C=A\cup B,
\]

set candidate neighbors of \(C\) to the union of neighbors of A and B.

Use a lazy priority queue.

If the candidate graph becomes disconnected and no valid merge remains while the budget has not been reached, use nearest current semantic centroids as a deterministic fallback.

Run candidate sensitivity with:

\[
k\in\{5,10,20\}.
\]

Report whether results change materially.

Do not hide that candidate proposals can affect the greedy result.

# 14. HYPEREDGE COLLAPSE — T4

\[

and partition \(P_k\), define:

\[

\]

\[
e^{(k)}
=
\{(C,m_C(e)):m_C(e)>0\}.
\]

- cluster multiplicities;
- snapshot;

\[

```json

  "supernodes": ["A", "B", "C"],
  "multiplicity": {
    "A": 3,
    "B": 1,
    "C": 1
  }
}
```

## Required cases

### Case 1: \(m=n\)

If all endpoints land in the same supernode:

- retain the hyperedge as an **internal hyperedge** attached to that supernode;
- do not silently delete it.

### Case 2: \(1<m<n\)

Collapse repeated endpoints to the supernode but retain multiplicity and remaining external endpoints.

### Case 3: ≥3 supernodes

Keep a genuine coarse hyperedge spanning all distinct supernodes.

Do not replace it with a set of pairwise edges.

## Explicit information loss

State that coarse representation loses exact individual endpoint identities at that resolution, but preserves:

- total original arity;
- endpoint multiplicities by supernode;
- relation type;
- provenance;
- original edge identity.

Write synthetic tests for all three cases.

\[
\sum_C m_C(e)=|e|.
\]

# 19. PAIRWISE BASELINE

Implement exactly one pairwise structural baseline.

Project every hyperedge of arity \(r\) into all unordered endpoint pairs.

To avoid automatically giving large hyperedges greater total mass, assign each pair contribution from hyperedge \(e\):

\[
w_{ij}^{(e)}
=
\frac{1}{\binom{r}{2}}.
\]

Aggregate duplicate pairs.

Use semantic compactness plus a normalized weighted graph-cut structural term:

\[
F_G(P)=
\frac{
\sum_{(i,j)}w_{ij}\mathbf{1}[c(i)\ne c(j)]
}{
\sum_{(i,j)}w_{ij}
}.
\]

Do not claim this baseline is equivalent to the native objective.

# 31. SIMPLE COARSE-TO-FINE RETRIEVAL

For each benchmark question:

1. embed the question with the retrieval encoder;
2. score all P0 clusters using the centroid of descendant candidate-document embeddings;
3. retain a beam;
4. score children;
5. continue to P2;
6. score candidate leaf nodes beneath surviving branches;
7. return top-k evidence/results.

Run beam widths such as:

\[
b\in\{1,3,5,10\}.

Do not train or tune beam width on gold results.

> number of cluster/node embedding comparisons performed.
