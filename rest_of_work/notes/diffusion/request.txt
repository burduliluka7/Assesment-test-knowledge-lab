Update the existing TKH retrieval implementation to address the remaining Type-A retrieval failure using **query-seeded relevance propagation over the native hypergraph**, based primarily on:

Dengyong Zhou, Jiayuan Huang, Bernhard Schölkopf,  
**“Learning with Hypergraphs: Clustering, Classification, and Embedding,” NIPS 2006.**

Do not create a disconnected implementation. Inspect the repository, current contextual retrieval code, current hypergraph operator, evaluator, artifacts, and configuration first. Reuse existing graph/snapshot/filtering infrastructure wherever possible.

The paper is especially relevant because the project already uses essentially the same normalized hypergraph operator for spectral geometry:

```text
Theta = D_v^(-1/2) H W D_e^(-1) H^T D_v^(-1/2)
```

Zhou et al. additionally derive transductive inference:

```text
f = (I - xi Theta)^(-1) y
```

where `y` is the initial signal and `f` is the signal propagated through the hypergraph.

The key experiment here is to replace supervised labels `y` with **query-dependent semantic relevance seeds**.

Do not merely cite the paper. Implement and test this mechanism.


```text
query-relevant information exists elsewhere in the graph,
```

```text

   ↓ strong semantic match
```


```text
DO NOT copy all evidence into every target entity.

Instead:

question
   ↓
semantic relevance seeds on graph nodes
   ↓
native hypergraph propagation
   ↓
relevance reaches structurally connected answer entities
```

# 3. FIRST: VERIFY THE PAPER OPERATOR AGAINST CURRENT CODE

Inspect the existing implementation of the hypergraph spectral operator.

The Zhou operator is:

```python
Theta = Dv^(-1/2) @ H @ W @ De^(-1) @ H.T @ Dv^(-1/2)
```

where:

```text
H  = incidence matrix
W  = diagonal hyperedge-weight matrix
De = hyperedge-degree / cardinality matrix
Dv = vertex-degree matrix
```

The current project already uses this or an equivalent sparse operation for spectral coordinates.

Do not duplicate it if a correct reusable implementation exists.

Add a reusable operation such as:

```python
apply_theta(x, snapshot_graph, relation_weights=None) -> vector
```

It should calculate `Theta @ x` using sparse incidence operations.

DO NOT construct a dense `n x n` Theta matrix during normal retrieval.

The graph has only thousands of nodes now, but the implementation should preserve the correct sparse formulation.

# 8. DO NOT COMPUTE THE MATRIX INVERSE

Zhou et al. write the transductive solution in closed form:

```text
f = (I - xi Theta)^(-1) y
```

Do not explicitly invert this matrix.

Implement the equivalent restarted iterative propagation:

```python
f_0 = y

f_{t+1} = (1 - alpha) * y + alpha * Theta @ f_t
```

For ranking purposes the constant scaling relative to the closed-form expression is irrelevant.

Use:

```text
0 < alpha < 1
```

Declare:

```text
alpha = 0.85
```

as the default retrieval diffusion parameter.

Also report non-tuned sensitivity for:

```text
0.50
0.70
0.85
0.95
```

Do not select the final value based solely on this development benchmark.

Stop iterations when:

```python
||f_next - f||_1 < tolerance
```

or a safe maximum iteration count is reached.

Suggested defaults:

```text
tolerance = 1e-8
max_iterations = 100
```

Document actual iterations-to-convergence.
