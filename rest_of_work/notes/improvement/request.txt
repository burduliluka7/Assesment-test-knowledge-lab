# 8. REPLACE CENTROID-ONLY SUPERNODE SEARCH WITH MULTI-PROTOTYPE SEARCH

The current hierarchy search appears vulnerable to centroid dilution:

a large heterogeneous supernode can have a centroid that is not close to a query even though it contains highly relevant descendants.

Improve this without changing the hierarchy.

For every non-singleton supernode, precompute a SMALL number of representative semantic prototypes from its descendant nodes.

For example 3–8 prototypes.

Use a deterministic method such as:

- medoids;
- farthest-point representatives;
- small deterministic k-medoids;
- or another transparent method.

Store prototypes by useful target-type family where feasible.

A supernode query score should combine:

- similarity to semantic centroid;
- maximum or top-k-mean similarity to prototypes.

For example:

score(C,q)
=
alpha * cos(q, centroid_C)
+
(1-alpha) * mean_top_r cos(q, prototype_i).

Use a prespecified reasonable alpha.

Do not tune alpha on the 18 benchmark questions.

If useful, perform a small generic sensitivity check and report it as sensitivity rather than selecting the best benchmark result.

Use the SAME underlying query embedding model for flat and hierarchical search.

# 9. USE BEST-FIRST HIERARCHICAL SEARCH

Replace or augment rigid fixed-beam traversal with a priority-queue best-first traversal.

Conceptually:

start with L0 nodes.

Score them.

Push promising supernodes onto a priority queue.

Repeatedly:

- pop highest-scoring unexpanded supernode;
- expand its children;
- score those children;
- charge every score operation to the inspection budget;
- retain eligible leaf/entity results;
- continue until budget exhausted or enough outputs obtained.

Maintain deterministic tie breaking.

Keep the existing fixed-beam approach available as a baseline or sensitivity comparison if inexpensive.
