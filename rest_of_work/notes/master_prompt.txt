# 7. Mandatory T4 hyperedge collapse

Suppose hyperedge e originally contains n endpoints.

After clustering, define

m_{e,C}

as the number of endpoints belonging to coarse supernode C.

Represent the coarse relation as:

{(C, m_{e,C}) : m_{e,C} > 0}.

Handle the required cases.

## Case 1: m = n

All endpoints belong to one supernode.

The hyperedge becomes INTERNAL to that supernode.

Do not retain it as a meaningful inter-supernode self-edge.

Preserve it as internal evidence/statistics/provenance.

## Case 2: 1 < m < n

Example:

{a,b,c,d}

with

a,b,c -> S1
d -> S2

becomes:

{S1:3, S2:1}.

Preserve:

* multiplicity;
* original arity;
* relation type;
* original edge identity;
* provenance.

## Case 3: at least three resulting supernodes

Example:

{a,b,c,d,e}

becomes:

{S1:2, S2:1, S3:2}.

Keep this as ONE hyperedge.

DO NOT replace it by the pairwise triangle:

S1-S2
S1-S3
S2-S3.

The collapsed hypergraph produced by this function must actually be used at the next resolution.

Add strong unit tests for all three cases.

# 8. Native hyperedge fragmentation objective

Use multiplicity directly.

For hyperedge e with original/current endpoint multiplicities, define:

p_{e,C} = m_{e,C} / n_e.

Define normalized fragmentation:

# phi_e(P)

(1 - sum_C p_{e,C}^2)
/
(1 - 1/n_e).

For n_e > 1.

Interpretation:

phi_e = 0

when every endpoint is contained in one cluster.

phi_e = 1

when every endpoint is maximally separated.

Importantly:

a 3+1 split and a 2+2 split do NOT receive identical treatment.

Define:

# J_hyper(P)

weighted mean of phi_e(P).

Use configurable relation weights.

Default all relation weights to 1 unless an actual experiment justifies something else.

Do not invent scientifically meaningful relation weights without evidence.

# 9. Hypergraph Laplacian

At each hierarchy resolution construct a native hypergraph incidence matrix.

Let:

B[u,e] = 1

when current supernode u participates in current non-internal hyperedge e.

Maintain multiplicities separately.

Define:

D_e[e,e] =
number of distinct current supernodes incident to e.

Let W contain hyperedge weights.

Define:

# D_v[u,u]

sum_e B[u,e] W[e,e].

Use the normalized hypergraph operator:

# Theta

D_v^(-1/2)
B
W
D_e^(-1)
B^T
D_v^(-1/2).

Then:

L_H = I - Theta.

Use sparse matrices.

Handle isolated nodes safely.

Verify numerically that the Laplacian is symmetric up to floating-point tolerance.

Compute a small configurable number of low-frequency eigenvectors.

Use those eigenvectors as a GLOBAL structural representation.

Do not rely on brittle eigenvector signs.

Explain the distinction:

J_hyper:
local, direct, multiplicity-aware preservation of actual hyperedges.

L_H spectral coordinates:
global structural geometry of the current hypergraph.

The two structural signals are related but not identical.

# 10. Semantic signal

Every node has `surface_form`.

Use a deterministic sentence-embedding model for clustering.

Normalize base embeddings.

For any supernode C:

mu_C =
member-count-weighted mean of the base embeddings.

Use a Ward-style semantic merge increase:

# Delta_sem(A,B)

n_A n_B / (n_A+n_B)
*
||mu_A - mu_B||^2.

Cache embeddings.

# 11. Spectral merge signal

For each current unit use its low-frequency spectral coordinate s_A.

For merging A and B define:

# Delta_spec(A,B)

n_A n_B / (n_A+n_B)
*
||s_A - s_B||^2.

The spectral representation is recomputed AFTER each completed hierarchy level on the actually collapsed hypergraph.

It does not need to be recomputed after every individual agglomerative merge inside the same level.

Document this clearly.

# 12. Temporal regularization — IMPORTANT

For the first temporal snapshot:

J_temp = 0.

For later snapshots compare the CURRENT candidate partition against the previous snapshot partition at the SAME hierarchy level.

Restrict comparison to persistent base nodes appearing in both snapshots.

Use Variation of Information:

# VI(P,Q)

H(P) + H(Q) - 2 I(P,Q)

=
H(P|Q) + H(Q|P).

Normalize it, for example by:

log(N_persistent)

when N_persistent > 1.

Call this:

J_temp(P_t, P_{t-1}).

This is preferable to a one-sided impurity because it penalizes BOTH:

* unnecessary splitting of an old community;
* unnecessary merging of previously separate communities.

Implement contingency-count updates so merge deltas can be computed efficiently.

New nodes that did not exist previously should not directly incur temporal penalties.

Temporal regularization must encourage continuity, NOT prohibit genuine change.

A sufficiently strong structural/semantic signal must still be able to create a legitimate split or merge.

# 14. Agglomerative hierarchy construction

Build bottom-up.

The singleton partition is P_K.

At each target level:

1. compute current hypergraph representation;
2. compute semantic centroids;
3. compute current hypergraph Laplacian;
4. compute spectral coordinates;
5. construct candidate merge pairs;
6. greedily/agglomeratively choose merges according to the hybrid objective;
7. stop at the configured hard budget;
8. save the partition;
9. collapse hyperedges using the T4 rule;
10. construct the next coarse hypergraph;
11. recompute its Laplacian;
12. continue.

Candidate merge pairs can come from the union of:

* shared hyperedge neighbors;
* semantic k-nearest neighbors;
* spectral k-nearest neighbors;
* previous-snapshot compatible clusters.

Do not evaluate all O(n^2) pairs unnecessarily.

A heap with lazy invalidation is acceptable.

The corpus is small, so optimize for clarity before extreme performance.

# 37. Mandatory tests

Write tests for scientifically important invariants.

## Hyperedge collapse

Test:

* m=n;
* partial internal collapse;
* 3+ resulting coarse nodes;
* multiplicity preserved;
* original arity preserved;
* provenance preserved;
* no accidental clique expansion.

## Hierarchy

Test:

* laminarity;
* no overlap;
* full coverage;
* exactly one parent;
* hard budgets.

## Spectral

On a tiny synthetic hypergraph test:

* incidence dimensions;
* symmetry;
* finite values;
* eigenvalues not substantially negative beyond floating error.

Do NOT test exact eigenvector signs.

## Temporal events

Synthetic cases:

* continuation;
* growth;
* split;
* merge;
* birth;
* death.

## Temporal honesty

Create future evidence and ensure an earlier snapshot cannot pass it to the labeller.

## Retrieval

Create a tiny hierarchy with a known target.

Verify:

* coarse-to-fine traversal;
* budget accounting;
* flat baseline accounting.

Pin dependencies.

different embedding family + random-label null.

Component:
temporal clustering

Optimization:
previous partition through VI penalty

Evaluation:
ARI/VI after real evolution and edge-removal perturbations

Control:
separate perturbation and real-snapshot experiments.

Component:
labels

Generation:
snapshot-visible cluster evidence

Evaluation:
independent NLI and/or blind human review

Control:
evaluation not performed by the same generation step.

Component:
extrinsic retrieval

Optimization:
hierarchy

Evaluation:
supplied question/ground-truth benchmark

Control:
same retrieval scorer and budget for flat and hierarchical systems.

This section is one of the most important deliverables.

Examples of VERIFIED facts:

* actual node count;
* actual edge count;
* actual arity distribution;

# 45. Questions / ambiguity handling

The assessment encourages asking questions early rather than silently guessing.

Codex itself cannot contact the assessors.

Therefore:

if the real dataset materially contradicts the documented schema or creates a genuine interpretation ambiguity:

1. document it in `QUESTIONS.md`;
2. choose the most conservative interpretation needed to continue;
3. mark it explicitly as an assumption;
4. do not hide it.

Do not create questions about things that can simply be determined by inspecting the supplied data.

# 48. Final scientific standard

The final submission should support a statement of this FORM only if the results justify it:

“We propose a recursive temporal spectral-semantic hypergraph coarsening method. Each resolution combines a native multiplicity-aware hyperedge objective, spectral coordinates computed from the current hypergraph, semantic embeddings, and temporal regularization. Hyperedges are explicitly collapsed after each level and the collapsed hypergraph is used at the next resolution. Laminarity and display budgets hold by construction, while semantic coherence, temporal stability and label faithfulness are treated as empirical claims and evaluated with independent signals.”

Do NOT automatically write:

“our method outperforms the baselines.”

Do not claim superiority until actual results support it.

The assessment explicitly rewards honesty about noisy, negative, and ambiguous results.
