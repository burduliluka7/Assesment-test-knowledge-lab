# 5. EVIDENCE PRIORITY

Use this generic priority when constructing candidate evidence:

```text
1. direct claim explicitly linked to candidate

2. claim explicitly mentioning candidate name

3. direct task/problem linked to candidate

4. direct evaluated_on / technique / component evidence

5. article that presents the candidate

6. article/claim evidence connected by a short,
   high-support propagation path

7. broader provenance evidence only as fallback
```

Prefer candidate-specific evidence over general article context.

# 7. AVOID GENERIC HUB EVIDENCE

The diffusion analysis showed that paths frequently pass through broad nodes such as:

```text

machine learning
large generic tasks

```

These can be useful for propagation but are poor evidence for final answer discrimination.

When constructing reranker evidence:

```text

```

Instead classify path nodes into:

```text

```

Generic bridges should remain available for provenance/path explanation but should normally not be included as semantic evidence text.

Implement a generic hub/genericness indicator using graph properties such as:

```text

```

Do not blacklist current benchmark names manually.

# 11. RR1 — DETERMINISTIC EVIDENCE-AWARE BASELINE

Before adding a cross-encoder, implement a transparent deterministic evidence reranker.

Score candidate-specific evidence against the question.

Use separate fields:

```text
candidate name
direct claims
explicit mentions
tasks/problems
technical evidence
datasets
article title
```

For multi-item fields use:

```text
max
or
mean of top 2
```

as already supported elsewhere.

The key difference from old R1/R3 is:

```text
the documents are candidate-specific
and created AFTER H2 candidate generation,
rather than broad static graph-node representations.
```

Implement an availability-aware score so sparse candidates are not automatically punished merely because some fields do not exist.

For example conceptually:

```python
available_semantic_score =
    weighted_sum_of_available_fields
    / sum_of_available_field_weights
```

BUT prevent a candidate with one lucky field from receiving unlimited advantage.

Use a fixed evidence-coverage confidence term such as:

```python
coverage =
    available_weight / total_possible_weight

final_score =
    available_semantic_score * coverage_adjustment
```

Choose a simple monotone adjustment before running evaluation.

For example:

```python
coverage_adjustment =
    0.5 + 0.5 * sqrt(coverage)
```

or another similarly mild fixed rule.

Document the choice.

Do not tune the rule against the benchmark.

Call this:

```text
RR1_evidence_semantic
```

# 31. IMPORTANT INTERPRETATION

The reranker has a different job from diffusion.

Document this clearly:

```text
semantic retrieval:
find query-relevant text

hypergraph diffusion:
transfer relevance from evidence to structurally related entities

candidate reranker:
determine which of those related entities
actually satisfies the question constraints
```

Do not claim the reranker fixes graph extraction.

Do not claim diffusion itself answers the question.
